The sorting office

A string arrives as a parcel. Behind these four desks the compiled moonucd opens it: it presses the text into a normalization form, sorts it into grapheme clusters, words and sentences, measures it in terminal cells, cuts it where a line may break, and files every character under its case forms. Nothing below is a re-implementation — every number and every glyph comes from the library's own tables, running as JavaScript in this page.

Desk one

The press

Normalization is a press with three plates: decompose every character, put the marks in canonical order, then compose what may be composed. The same text can look identical and be different — é as one code point or as e and a combining acute. Run the plates and see which characters move.

Desk two

The belt

A terminal, a cursor and a line wrapper all count in cells, and they may only cut between grapheme clusters: a flag, an emoji sequence and a letter with its accents are one cluster each. The belt is drawn at one character per cell, so what you see is what a terminal would give the text.

Desk four

The case rack

Every character is filed under six answers: the full uppercase, lowercase and titlecase mappings, which may turn one character into several; the simple ones, one character in and one out; the full fold used to compare without case; and the class the simple fold joins, which is how a matcher closes a set under case without walking the code space.

A dash means the mapping changes nothing. The orbit is the whole class, itself included.
